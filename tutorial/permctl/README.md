# `permctl` — the tutorial application

`permctl` is the worked example for LeanPort: a stdlib-only Go command-line tool
whose authorization policy is written and proved in Lean 4, compiled to native
code, and called through a generated binding.

It demonstrates one claim: *a Go developer can use verified Lean logic without
writing C glue or learning Lean's native linking.*

The project is checked in complete and is exercised by
[`../../scripts/e2e.sh`](../../scripts/e2e.sh).

## Layout

```
permctl/
├── go.mod
├── leanport.toml                        # modules, exports, types, targets
├── lean/
│   ├── lean-toolchain                   # leanprover/lean4:4.29.1
│   ├── lakefile.toml
│   └── LeanPort/Authz/
│       ├── Policy.lean                  # levels, actions, authorize
│       ├── Proofs.lean                  # machine-checked guarantees
│       ├── Boundary.lean                # scalar boundary + @[export]
│       └── SPEC.md                      # generated by `leanport docs`
├── internal/verified/authz/             # GENERATED by `leanport build`
│   ├── authz.go                         # type Action, constants
│   ├── authz_cgo.go                     # cgo layer + func Authorize
│   ├── artifact.go                      # archive digest
│   ├── native/linux_amd64/libAuthz.a    # 27 KB, runtime-free
│   └── MANIFEST.json                    # toolchain, exports, mode, digests
└── cmd/permctl/
    ├── main.go                          # decide / matrix / verify / version
    └── main_test.go                     # asserts the matrix and exit codes
```

## Policy under verification

Four access levels, five actions. The policy receives *facts* — authenticated,
admin, owns-this-resource — never a client-supplied role.

| Level | create | read | update | delete | viewAudit |
|---|---|---|---|---|---|
| unauthenticated | deny | deny | deny | deny | deny |
| member | allow | deny | deny | deny | deny |
| owner | deny | allow | allow | allow | deny |
| admin | allow | allow | allow | allow | allow |

Theorems proved in `Proofs.lean`:

- `unauthenticated_denied` — every action is denied when unauthenticated;
- `unauthenticated_cannot_become_admin` — no combination of flags grants admin
  to an unauthenticated caller;
- `member_can_create`, `member_cannot_read_others`;
- `owner_can_read`, `owner_can_update`, `owner_can_delete`;
- `owner_cannot_view_audit`;
- `admin_can_everything`;
- `audit_requires_admin` — audit access equals `authenticated && admin`.

## CLI surface

| Command | Behaviour |
|---|---|
| `permctl decide --auth [--admin] [--owner] --action <create\|read\|update\|delete\|viewAudit>` | Prints `allow` or `deny`; exit `0` or `1`. |
| `permctl matrix` | Prints the level × action table resolved through the verified module. |
| `permctl verify` | Asserts 39 checks: 20 cells, ownership variants, unauthenticated-with-flags, admin-who-owns, and invalid codes. |
| `permctl version` | Prints version (injected with `-ldflags`). |

## Run it

```bash
leanport check
leanport build
go test ./...
go run ./cmd/permctl verify
go run ./cmd/permctl matrix
go run ./cmd/permctl decide --auth --owner --action delete
```

## Boundary implementation notes

`permctl` is decision logic, so its boundary is deliberately **runtime-free**:

- decode `UInt8` codes with `==`, not `Option`;
- encode the result as `UInt8` (`1` allow, `0` deny);
- invalid action codes return `0` (fail closed);
- no `deriving Repr`, no `Nat`, no allocation on the exported path.

The archive is about 27 KB (it includes the compiled proofs) and adds no Lean
runtime to the Go binary (`ldd` shows only libc). That is a choice for this
module, not a LeanPort limit: `String` and `ByteArray` exports use runtime-linked
mode — see [`../../examples/rich-types/`](../../examples/rich-types/). Arrays,
records and `Option` have validated ABI mappings but no generator yet.

## Acceptance criteria

1. `leanport check` exits `0`; with an injected `sorry` it exits non-zero and
   names the file.
2. `leanport build` produces a linking Go package with no Lean runtime
   dependency.
3. `go test ./...` passes.
4. `permctl verify` agrees with the table for every cell and variant.
5. `permctl decide` exits non-zero when it denies, so it composes in shell.
6. The whole flow works from a fresh clone following
   [`../README.md`](../README.md), on the non-Nix path, and is reproduced by
   [`../../scripts/e2e.sh`](../../scripts/e2e.sh).
