# `permctl` — the tutorial application

> **Status: pre-alpha.** File map and acceptance criteria are specified;
> implementation follows the tutorial.

`permctl` is the worked example for LeanPort: a stdlib-only Go command-line tool
whose authorization policy is written and proved in Lean 4, compiled to native
code, and called through a generated binding.

It exists to demonstrate one claim: *a Go developer can use verified Lean logic
without writing C glue or learning Lean's native linking.*

## Policy under verification

Four access levels, five actions. The policy receives *facts* — authenticated,
admin, owns-this-resource — never a client-supplied role.

| Level | create | read | update | delete | viewAudit |
|---|---|---|---|---|---|
| unauthenticated | deny | deny | deny | deny | deny |
| member | allow | deny | deny | deny | deny |
| owner | — | allow | allow | allow | deny |
| admin | allow | allow | allow | allow | allow |

Theorems proved in `Proofs.lean` include:

- `unauthenticated_denied` — every action is denied when unauthenticated;
- `unauthenticated_cannot_become_admin` — no combination of flags grants admin
  to an unauthenticated caller;
- `member_can_create`, `member_cannot_read_others`;
- `owner_can_read`, `owner_can_update`, `owner_can_delete`;
- `owner_cannot_view_audit`;
- `admin_can_everything`;
- `audit_requires_admin` — audit access equals `authenticated && admin`.

## CLI surface

| Command | Behaviour |
|---|---|
| `permctl decide --auth [--admin] [--owner] --action <create\|read\|update\|delete\|viewAudit>` | Prints `allow` or `deny`; exit `0` or `1`. |
| `permctl matrix` | Prints the level × action table resolved through the verified module. |
| `permctl verify` | Asserts all twenty cells with owner/other-owner variants; exit non-zero on mismatch. |
| `permctl version` | Prints version (injected with `-ldflags`). |

## Acceptance criteria

1. `leanport check` exits `0`; with an injected `sorry` it exits non-zero and
   names the file.
2. `leanport build` produces a linking Go package with no Lean runtime
   dependency.
3. `go test ./...` passes in `permctl`.
4. `permctl verify` agrees with the table for every cell.
5. `permctl decide` exits non-zero when it denies, so it composes in shell.
6. The whole flow works from a fresh clone following `../README.md`, on the
   non-Nix path, and is reproduced by `scripts/e2e.sh`.

## Boundary implementation notes

`permctl` is decision logic, so its boundary is deliberately **runtime-free**:

- decode `UInt8` codes with `==`, not `Option`;
- encode the result as `UInt8` (`1` allow, `0` deny);
- invalid action codes return `0` (fail closed);
- no `deriving Repr`, no `Nat`, no allocation on the exported path.

That keeps the archive at a few kilobytes and adds no Lean runtime to the Go
binary. It is a choice for this module, not a LeanPort limit: exports that use
`String`, `ByteArray`, arrays, records or `Option` are supported through
runtime-linked mode (see [`../../docs/limitations.md`](../../docs/limitations.md)),
at the cost of a larger archive.
